Perguntas e Respostas sobre Git

  1. Pergunta 1

    O que são operações de “Commit”, “Push” e “Pop” efetuadas num repositório?

    As operações Commit, Push e Pop são ações essenciais num repositório Git. O Commit é utilizado para registar e guardar alterações no repositório local, criando um ponto de controlo no histórico do projeto. O Push tem a função de enviar esses commits para o repositório remoto, permitindo a partilha das atualizações com outros utilizadores. Já o Pop é usado para recuperar alterações temporariamente guardadas com o comando stash, retomando o trabalho que havia sido interrompido. Estas operações garantem um fluxo de trabalho organizado e seguro no desenvolvimento colaborativo.

  2. Pergunta 2

    Quais são as vantagens de usar Branches num repositório Git?

    O uso de branches num repositório Git oferece diversas vantagens no desenvolvimento de software:

    • Permite que novas funcionalidades, correções ou testes sejam realizados de forma isolada, sem afetar o código principal.
    • Garante maior segurança, organização e controlo de versões.
    • Facilita o trabalho colaborativo, permitindo que vários programadores desenvolvam em paralelo sem conflitos diretos.
    • Contribui para um fluxo de trabalho mais estruturado e eficiente, com integração controlada das alterações.

  3. Pergunta 3

    Nos Merges de conteúdos resultantes de um “Pop” podem resultar em conflitos. Em que consistem e como podem ser resolvidos?

    Conflitos em merges após um Pop ocorrem quando alterações no branch local e no branch remoto ou na pilha de commits do stash modificaram a mesma parte de um arquivo de formas diferentes. Eles podem ser resolvidos manualmente, editando o arquivo para escolher ou combinar as mudanças corretas, e depois finalizando o merge com um commit.

  4. Pergunta 4

    “Clone” e “Fork” são formas diferentes de replicar um repositório Git. Quais as diferenças entre eles?

    O Clone cria uma cópia local completa de um repositório existente, incluindo todo o histórico, permitindo trabalhar diretamente nele. Já o Fork cria uma cópia do repositório no próprio perfil do usuário (geralmente em plataformas como GitHub), permitindo modificar e enviar contribuições via pull request sem alterar o repositório original.
