 
1 - O que são operações de “Commit”, “Push” e “Pop” efetuadas num repositório?
2 – Quais sáo as vantagens de usar Branchs num repositório git?
3 – Nos Merges de conteúdos resultantes de um “Pop” podem resultar em conflitos. Em
que consistem e como podem ser resolvidos esses conflitos?
4 – “Clone” e “Fork” são formas diferentes de replicar um repositório Git. Quais as
diferenças entre eles?

Resposta Pergunta 1

As operações Commit, Push e Pop são ações essenciais num repositório Git. O Commit é utilizado para registar e guardar alterações no repositório local, criando um ponto de controlo no histórico do projeto. O Push tem a função de enviar esses commits para o repositório remoto, permitindo a partilha das atualizações com outros utilizadores. Já o Pop é usado para recuperar alterações temporariamente guardadas com o comando stash, retomando o trabalho que havia sido interrompido. Estas operações garantem um fluxo de trabalho organizado e seguro no desenvolvimento colaborativo.


Resposta a pergunta 2.

O uso de branches num repositório Git oferece diversas vantagens no desenvolvimento de software. Permite que novas funcionalidades, correções ou testes sejam realizados de forma isolada, sem afetar o código principal. Essa separação garante maior segurança, organização e controlo de versões. Além disso, facilita o trabalho colaborativo, permitindo que vários programadores desenvolvam em paralelo sem conflitos diretos. Por fim, os branches contribuem para um fluxo de trabalho mais estruturado e eficiente, com integração controlada das alterações.

Resposta a pergunta 3 

Conflitos em merges após um “Pop” ocorrem quando alterações no branch local e no branch remoto ou na pilha de commits do stash modificaram a mesma parte de um arquivo de formas diferentes. Eles podem ser resolvidos manualmente, editando o arquivo para escolher ou combinar as mudanças corretas, e depois finalizando o merge com um commit.

Resposta Pergunta 4

“Clone” cria uma cópia local completa de um repositório existente, incluindo todo o histórico, permitindo trabalhar diretamente nele. Já “Fork” cria uma cópia do repositório no próprio perfil do usuário (geralmente em plataformas como GitHub), permitindo modificar e enviar contribuições via pull request sem alterar o repositório original.
